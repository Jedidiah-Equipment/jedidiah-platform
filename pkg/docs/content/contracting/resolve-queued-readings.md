# Resolve queued readings

1. Open **Needs attention** from **Machines**. Read the reason beside each refused capture.
2. If another reading landed first, review the last known reading shown (connect to load it if needed). If that value is wrong, choose **The previous reading is wrong · resubmit as dispute**. The original capture and photo return to the queue. If another reading arrives before this dispute syncs, it stays in Needs attention for you to review again.
3. To remove a capture instead, choose **Discard capture**, then **Confirm discard**. This permanently removes the local capture and photo.
4. Keep the app open with a connection, or choose **Try sync now**. Later captures for the same Machine wait until the earlier refused capture is resolved. Other Machines continue syncing.

A connection or sign-in failure leaves captures queued for retry. If your role no longer permits capture, the refused item stays in Needs attention. For a refusal that does not offer a dispute, ask management to check the Machine before deciding whether to discard and capture again.
