# Jedidiah Contracting

## Summary
### Flow Summary
Scoped a new JedConOps contracting app for job cards, machine hours, breakdowns and servicing. Deano to spec schema and decide whether to build inside JedOps or standalone.

### JetConOps Job Card Flow
- Foreman opens job card in app, selects machine by code, logs start/stop hours; Henk signs off, Jed van Niekerk applies rates, Karen invoices in PESTEL
- Machine hours run sequentially: closing hours on job A = opening hours on job B; farmer at destination pays travel
    - Unaccounted-for gaps flagged; only Jed van Niekerk/Henk can resolve with a reason
- Photo of hour meter preferred, AI reads value; manual entry allowed but flagged as missing photo evidence
- Jobs pre-created by admin (customer, description); foreman selects from list, job auto-starts on first machine start

### Breakdowns, Servicing & Notifications
- Separate breakdown reporting from scheduled servicing; both tracked per machine with history
- Voice notes transcribed via AI with tunable prompt for local names/dialects; users can edit, diffs feed back to improve
- Notifications via read-only WhatsApp broadcast channel instead of building in-app push
- Mechanic performance tracked by time-to-close; workshop manager (Connor) assigns one primary mechanic per breakdown

### Architecture & Roles
- Undecided: build inside JedOps (shared codebase, mode switcher) vs fully standalone app
    - Only Jed van Niekerk, Reino, Karen need cross-access; staff otherwise fully separated
- Roles: super admin, contracting manager (Henk), foreman, workshop manager (Connor), mechanics and drivers as non-login users
- Machine availability derived from active jobs; categories (excavator, TLB, etc.) enable utilisation reporting over time

### Next Steps
- (Jed van Niekerk) Motivate pros and cons of shared vs standalone app before build starts
- (Jed van Niekerk) Call Reinhard Zellhuber tonight to catch up on the breakdown
- (Reinhard Zellhuber) Decide where the contracting app will live (inside JedOps or standalone)
- (Reinhard Zellhuber) Draft rough spec and schema (jobs, fleet, machines, drivers, roles) for agreement

### Decisions Made
- Promote Bon Gauze to run fabrication; Sean moves from CNC to supply
- Foreman selects jobs from pre-created list; only Henk closes jobs and stamps final start/end dates
- Notifications via read-only WhatsApp broadcast channel, not a custom in-app system
- Photo of hour meter is primary capture method; manual entry allowed but flagged
- One primary mechanic assigned per breakdown to keep performance metrics clean
